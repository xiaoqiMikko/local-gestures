# Local Gestures

[English](README.md) · 简体中文

一个**从不联网**的 Chrome / Edge 鼠标手势扩展。

**零网络请求、无统计、无账号、无远程配置。** 你的浏览数据不会离开这台机器 ——
而且这件事**你可以自己花十秒钟验证**,不用信这份文档(见
[怎么自己验证](#怎么自己验证))。

Manifest V3 原生。English / 简体中文 / 繁體中文。

---

## 为什么会有这个东西

Manifest V2 从 Chrome 138(2025 年 7 月)起在稳定版彻底不能运行,
**2026 年 8 月 31 日** Google 会把商店里最后一批 MV2 扩展全部下架。
不少老牌手势扩展没能完成迁移,用户只能被推向还活着的那几个。

手势扩展处在一个特别敏感的位置:**它要能工作,就必须看到你在每一个页面上的鼠标动作。**
这恰好是做数据采集最想要的权限。

所以真正值得问的不是「哪个功能多」,而是:

> **「我能不能查清楚,它拿这份权限干了什么?」**

这个扩展是照着「能被查清楚」来做的。

## 功能

下面每一项都已实现,并被端到端测试覆盖。

| 触发方式 | 说明 | 默认 |
|---|---|---|
| **笔画手势** | 按住手势键画。预置 19 个手势,最多支持三段 | 开 |
| **摇杆手势** | 按住一个键,点另一个键 | 开 |
| **滚轮手势** | 按住手势键滚滚轮 | 开 |
| **超级拖拽** | 拖链接 / 图片 / 选中文字,**拖的方向**决定做什么 | 开 |
| **弹出轮盘** | 按住不动,八个动作在光标周围展开 | 关 |
| **简单拖拽** | 空白处按左键直线拖 | 关 |
| **双击** | 只在页面空白处生效 —— 双击文字仍然是选词 | 关 |
| **触摸手势** | 多指划动,和鼠标共用同一张手势表 | 关 |
| **右键菜单** | 把常用动作放进右键菜单 | 关 |
| **工具栏图标** | 点一下执行任意动作 | 打开设置 |
| **键盘快捷键** | 四个槽位,按键组合在 Chrome 自己的快捷键页面设置 | 开 |

**45 个动作**,覆盖导航、标签页、窗口、滚动、缩放和页面工具。

另有:实时手势轨迹、画的时候显示将执行的动作名、按站点禁用列表、
配置导入导出,以及设置页里的手绘板 —— 新手势直接画出来就行,不用背 `DRU` 这种写法。

### 几个值得记住的默认手势

| 手势 | 动作 |
|---|---|
| `←` / `→` | 后退 / 前进 |
| `↑` / `↓` | 滚到顶部 / 底部 |
| `↓→` | 关闭标签页 |
| `↓↑` | 恢复关闭的标签页 |
| `↑↓` | 刷新 |
| `←→` / `→←` | 下一个 / 上一个标签页 |

**按住右键点左键 = 后退**,**按住右键滚滚轮 = 切换标签页** —— 这两个不用画,最快。

## 怎么自己验证

别信 README,自己查。在源码目录里:

```bash
# 1. 全部源码里没有任何网络 API
grep -rn "fetch(\|XMLHttpRequest\|WebSocket\|EventSource\|sendBeacon" src/
#    -> 只会匹配到「这里没有网络调用」那句注释本身

# 2. 没有主机权限、没有请求拦截、没有历史记录权限
grep -n "host_permissions\|webRequest\|\"history\"\|\"cookies\"" manifest.json
#    -> 无匹配

# 3. 或者直接跑检查脚本,上面这些它都会断言
python tools/verify.py
```

`tools/verify.py` 会在出现网络调用、过宽权限、漏翻译的文案、
或指向不存在动作的配置时**直接让构建失败**。

### 它到底要了哪些权限,为什么

| 权限 | 用途 | 能更小吗 |
|---|---|---|
| 访问所有网站 | 手势必须能在你当前所在的页面上被识别。扩展只监听鼠标 / 滚轮 / 触摸输入并绘制轨迹,**不读取页面内容,也不往任何地方发送东西** | 不能 —— 这是手势扩展的固有代价。也正因如此,上面那几条自查才重要 |
| `tabs` | 执行你绑定的标签页动作(关闭 / 切换 / 固定 / 复制),以及「复制标题 / 复制网址」时读取当前标签的标题和网址。**那段文字只会进你的剪贴板** | 不能 |
| `sessions` | 「恢复关闭的标签页」 | 不能 |
| `search` | 拖拽搜索。用的是**你浏览器自己的默认搜索引擎** —— 这个扩展里不含任何搜索网址,也不知道你用的是哪家 | 不能 |
| `contextMenus` | 可选的右键菜单项,默认关闭 | 不能 |
| `downloads` | **可选,安装时不申请。** 只有你把某个拖拽方向设成「下载」时才会问你要,随时可以在设置里撤销 | 能 —— 默认就没有 |
| `bookmarks` | **可选,安装时不申请。** 只有你绑定「添加书签」动作时才会问你要,同样可撤销 | 能 —— 默认就没有 |

配置存在 `chrome.storage.local`。**不是 `sync`** —— 你的手势配置也不会被上传到 Google 账号。

## 安装

**从源码装**(商店上架前):

1. 下载或克隆本仓库
2. 打开 `chrome://extensions`
3. 打开右上角的**开发者模式**
4. 点**加载已解压的扩展程序**,选中仓库目录

支持任何带 MV3 的 Chromium 浏览器:Chrome、Edge、Brave、Vivaldi。需要 Chrome 116 及以上。

## 已知限制

写在前面,免得你自己撞上:

- **手势不能跨 iframe。** 从页面开始画、拖进内嵌框架里,笔画会断在边界上。
  所有基于 content script 的手势扩展都有这个问题。
- **`chrome://` 开头的页面、扩展商店、别的扩展的页面上没有手势。**
  Chrome 禁止在这些地方注入 content script,谁也做不到。
- **简单拖拽和双击默认关闭**,因为它们会和选择文字抢操作。你能接受再开。
- **只有四个方向**,没有斜向。斜向会让画手势的精度要求翻倍,收益却很小。

## 开发

```bash
python tools/verify.py     # 静态一致性 + 隐私承诺检查
python tools/e2e_test.py   # 拉起真实浏览器,把每种输入方式都跑一遍
python tools/demo.py       # 打开演示页,手动试
```

端到端测试断言的是**可观察的结果** —— 网址变了、标签页数变了、
滚动到了文档自身的最大位置 —— 而不是「处理函数有没有被调用」。共 109 项。

> ⚠️ **别用 Playwright 自带的 Chromium 截图或判断样式。**
> 在部分机器上它启动时不加载浏览器默认样式表,所有块级元素都会变成
> `display: inline`:表格塌成一行,`<style>` 标签的内容被当正文画出来。
> 页面看着全坏,但换成系统 Chrome 一切正常。
> 涉及渲染的脚本(`gen_screenshots.py`)都走系统 Chrome,并且会先断言
> `body` 的 display 是 `block`,不对就直接终止。

新增一个动作要改四个地方,漏了哪个 `verify.py` 都会告诉你:

1. `src/common/actions.js` —— 声明 id、分组、在哪一侧执行
2. `src/background/service-worker.js` 或 `src/content/content.js` —— 实现它
3. `tools/gen_locales.py` —— 补上三种语言,然后重新运行
4. 需要的话,在 `src/common/defaults.js` 里给个默认绑定

三种语言的文案都放在 `tools/gen_locales.py` 的同一张表里,由脚本生成到
三个 `_locales` 目录,所以 key 不可能对不上。图标同理,来自 `tools/gen_icons.py`。

## 反馈

Bug 和需求请提 issue。如果某个网站上手势不生效,**请附上网址** ——
这几乎总是 iframe、或者那个页面吞掉了鼠标事件,无论哪种都值得记录下来。
